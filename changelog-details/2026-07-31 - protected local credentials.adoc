= Protected local credentials (0.3.0)

== Why not a password hash?

A one-way hash is correct for *verifying* a password the user types again (e.g. `/etc/shadow`).
It is useless for a CLI that must *replay* the password to code.dlang.org on later runs.
Reusable registry secrets must be stored with reversible protection, not a hash.

== What we store

`login --user NAME --save-credentials` writes protected credentials after taking a password from (in order) `-p` / `--password-file` / `--password-stdin` / env / the default `password.incoming` drop file / `--prompt-password`.

Default drop file (deleted after a successful save):

* Windows: `%LOCALAPPDATA%\dlang-supplemental\dub-publish\password.incoming`
* macOS / Linux: `~/.dlang-supplemental/dub-publish/password.incoming`

Stored credentials file:

* Windows: `%LOCALAPPDATA%\dlang-supplemental\dub-publish\credentials.v1`
* Unix: `~/.dlang-supplemental/dub-publish/credentials.v1`

Format:

----
version=1
user=<username>
password=dpapi:<base64>   # Windows DPAPI, current user
# or
password=file:<base64>    # non-Windows; file mode 0600
----

`logout` deletes `credentials.v1` and any legacy plaintext `credentials` file.

== Migration

Pre-0.3.0 plaintext two-line `credentials` files are read once, then rewritten in the protected format and removed.
